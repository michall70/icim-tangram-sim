## 4. 平行四边形手性：口径确认（我们已经决定仿真里自动翻面）

**代码**：`planning/assign.py:113-135` 的 `handedness_mismatch`，`assign_ids` 在 `kind=="P"` 且判为
mismatch 时**抛 `AssignError`**（:184-193），整批规划中止。

**我们实测**（拿模型里那块的真实轮廓 → 经我们的 `HOMOGRAPHY` 投到像素 → 直接调你们这个函数）：

```
direct = 1.12 mm    mirror = 57.51 mm    mismatch = False
```

**但我们认为这个判据的口径值得跟你们对齐**（不是 bug，是"通过"的含义）：

- `handedness_mismatch(vertices)` 收到的 `vertices` 是**像素坐标**，y 轴朝下
  （`tangram_detector.py:482` 的 `_order_points` 按极角排序，排序方向受 y 轴向影响）；
- 而 `library` 是 y 向上的标准形 `[[0,0],[0.5,0],[0.75,0.25],[0.25,0.25]]`。

所以"通过"其实等价于：**实物那个平行四边形是翻面朝下摆的**。这和你们
`config.py:103-105` 的注释完全对得上——"2026-10-27 … 改为把绿色平行四边形实物翻面使其实测手性与本模板一致"。

**我们要问的**：现场那块绿块，**现在确实是翻面朝下摆的**吗？

- 如果是 → 我们仿真按同样状态跑（现在就是），报告里也照这个写，不用做任何事；
- 如果哪天换回"正面朝上" → `assign_ids` 会直接抛错，这时候只能靠"自动翻面"救。

**我们的决定**：按"优先保证任务完成"处理 —— 仿真侧**两条判据都算**，任一说要翻就翻：

- `assign.handedness_mismatch()`（像素空间）→ `icim_sim/chirality.py::check()`
- `plan_puzzle` 的 `suspected_flip`（毫米空间）→ `chirality.pattern_handedness()`
  （把模型里这块板的真轮廓造成一个 `TangramPiece`，**调一次你们的 `plan_puzzle`** 看它怎么说）

翻面 = 绕水平轴转 180°（七巧板是等厚棱柱，翻面后外形就是镜像，落回托盘还是平的），
物理上合法，不是作弊。

**实测（重要）**：`data/target_samples` 的三张图，在"不翻面"时都是 `suspected_flip=True`：

| 目标图 | 不翻面：拟合 / 镜像 | 翻面后：拟合 / 镜像 |
|---|---|---|
| `target_mine.png` | 12.53 / **1.29** → 疑似翻面 | **1.28** / 12.53 → 正常 |
| `target_square.png` | 12.21 / **1.14** → 疑似翻面 | **1.23** / 12.21 → 正常 |
| `target_triangle.png` | 12.49 / **1.13** → 疑似翻面 | **1.25** / 12.47 → 正常 |

也就是说：**你们的三张样例图都要这块板翻面**才能过 `validate_plan_geometry`，而
`assign` 那条判据在两种状态下都说"正常"。两条判据的口径是反的（§4.1），建议你们确认哪条为准。

### 4.1 为什么两条判据会打架

- `handedness_mismatch()` 收的是**像素**顶点（v 向下），`library` 是 y 向上的标准形；
- `plan_puzzle` 的拟合在**毫米**空间，模板多边形来自目标图（也是像素口径）；
- 于是"同一块板、同一个图案"，一条说符合、一条说反了。这不影响我们的仿真（两条都算、
  谁说要翻就翻），但真机上只有一条判据能兑现，请确认现场以哪条为准。

## 9. 目标图通道会把图案**上下镜像**（建议改，一行的事）

**现象**：目标图解析出来的七块，落到台面时相对图片是上下翻转的。

**证据**（我们按标准七巧板画的图，锚点 y = −430.65）：

| 块 | 图片里（台面 mm，y 向上） | 你们程序算出来的 | 关系 |
|---|---|---|---|
| 中三角 M | 形心 (197.7, **−391.9**) | 形心 (197.9, **−469.6**) | 绕锚点对称 |
| 正方形 Q | 形心 (158.9, **−401.6**) | 形心 (159.0, **−459.8**) | 绕锚点对称 |

每块都满足 `y' = 2·anchor_y − y`，也就是 `y → −y`。

**代码路径**（三处，中间没有翻 y 的动作）：

1. `target_image.normalize()` 交出来的多边形还是**像素坐标**（v 轴向下）；
2. `pattern.transform_polygon()` 只做"缩放 → 旋转 → 平移"；
3. 之后 `pattern.solution_to_pieces()` 用 `inv(H)` 回像素、`puzzle_planner._piece_geometry()`
   再用 `H` 转毫米——**一来一回抵消**，镜像一路保留到 `place_pose`。

**影响**：正方形、镜像对称的图形看不出来（镜像后还是同一个正方形），所以你们跑
`target_square` 没问题；V 形、三角形、任何不对称图案会**反着拼**。

**建议改法**（二选一）：

- (a) 代码：`normalize()` 归一化之后加一句 `normalized[:, 1] *= -1`，`piece.target_mm` 同步（同一处循环，一行）；
- (b) 现场：`cv2.flip(img, 0)` 把图上下翻再喂进去（缺点是人看图也得反着看）。

**注意联动**：改 (a) 之后，`handedness_mismatch`（§4.1）的含义会跟着反过来，那时候现场
"翻面朝下"的绿块反而会报不符。这两处要一起动，改完请用一块**正面朝上**的平行四边形重测。

**怎么快速验证**：拿 `data/target_samples/target_mine.png`（164×153，明显不对称）跑一次
`plan_preview.png`，把绿框和原图并排放——绿框应该是原图**上下翻**过来的样子。
