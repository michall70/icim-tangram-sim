# 这个仿真做了什么、没做什么

说清楚边界，免得把仿真里"能做"当成真机"能做"。

## 做了什么

| 方面 | 情况 |
|---|---|
| 几何 | 全部来自比赛 STEP：底座、托盘、七块板、末端工具的形状与位置 |
| 运动学 | 6 轴逆解/正解，关节零位与控制器读数一一对应（`joint_offsets.json`） |
| 关节限位 | FR3-C 手册的软限位（J1 ±175°，J2 +85/−265°，J3 ±150°，J4 +85/−265°，J5 ±175°，J6 ±175°） |
| 重力 | 开，七块板会落在托盘上、会翻、会滑 |
| 接触 | 板 ↔ 托盘面（每块托盘一张不可见碰撞面，顶面 = CAD 里板子的落点） |
| 相机 | 1280×720，内参 fx/fy≈911、cx/cy≈645.5/364.9，**带真实镜头畸变**（K、D 来自你们的标定） |
| 吸盘 | 对准 + 贴住才吸住（判据见 `API.md` §4），吸住后刚性跟随 |
| 可视化 | MuJoCo 被动窗口、腕相机预览、录像回放 |

## 没做（重要）

### 1. 机械臂没有碰撞

连杆的几何 `contype=0`，**机械臂会穿过七巧板、托盘、它自己**。
只有吸盘口对板子有"吸附判据"，没有任何连杆碰撞。

所以：仿真里能到达的位姿，真机上可能撞。要判碰撞只能看画面，或者自己在外层加检查。

### 2. 机械臂是运动学驱动，不是力矩驱动

每帧直接写关节角（`qpos`），不是通过电机/力矩。**每一步都会把臂重新钉回命令值**
（`_settle()` 里 `mj_step` 之后立即恢复 qpos/qvel），所以连接触反力也传不到臂上——
2026-11-02 之前没钉，吸盘压到板子那一刻的冲量会把 J6 踢转 13°/帧（677°/s），
表现成"下放时手腕突然转一下"，落点跟着偏 2–12 mm。因此：

- 没有动力学滞后、没有超调、没有重力下垂，也没有接触反力带来的抖动；
- 速度上限是代码里写死的 `speed_deg_s=180`（`vel=20%` 时 36°/s），不是仿真出来的；
- 撞到东西不会停（因为没有碰撞）。

### 3. 吸盘是几何吸附，不是气流

判据是"位置 + 姿态 + 间隙"，没有真空度、没有漏气、没有偏载。
板子被吸住后是**刚性**跟随，不会斜着掉下来。

### 4. 没有深度图、没有 RGB-D 噪声

`get_aligned_frames()` 返回 `(color, None, intrinsics)`，只够跑彩色流程。

### 5. 图像是渲染的，不是相机噪声模型

没有运动模糊、没有噪声、没有过曝/欠曝、没有反光。颜色是 `scene.xml` 里写死的
rgba（按真实七巧板的颜色配的），HSV 阈值才因此能直接用。

### 6. 七块板只在**开局**可能被翻面，搬运过程中不会

板子是 2.5 mm 的平板，被吸起来之后始终平躺，**搬运过程中不会翻面**。

唯一例外：平行四边形有手性问题（见 `API.md` §7.3）。换目标图以后，如果图案要求的
是另一只手，仿真会在**开局**把这块板绕水平轴翻 180° 再开始（`cell.flip_piece()`）——
七巧板是等厚棱柱，翻过来外形就是镜像、落回托盘仍然是平的，物理上合法。
这一步只在初始化时做一次，不参与后续任何动作，也不改变"搬运中不翻面"这条。

### 7. 板与板之间**不碰撞**（刻意）

七块板只和托盘垫片碰撞（`contype=4 / conaffinity=1`），彼此之间不碰。
原因：拼图块是紧贴的，而实物件比目标图案的槽位略大（正方形 +5%、平行四边形 +7%），
一旦允许互相碰撞，刚放下的块会被邻居顶开 6–8 mm，成品看着"缝很大"。
代价是块与块可能互相**穿插**零点几毫米 —— 这是按"视觉优先"刻意接受的取舍。

## 结论怎么用

| 仿真里看到 | 能推出什么 |
|---|---|
| 逆解能到某位姿 | 真机能到（限位、几何一致），但**不保证路径不撞** |
| 七块板落位误差 ≤ 0.7 mm | 视觉→规划→执行的链路自洽；不等于真机精度 |
| 吸盘吸不住（歪/远） | 真机大概率也吸不住 |
| 算法跑通 | 你们的逻辑在这一版输入下成立；不等于真机成立 |

真机精度取决于标定（`docs/FINDINGS.md` 里两条还没核对的数）、末端实物、以及现场光照。
